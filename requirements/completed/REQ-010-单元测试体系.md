- pytest - Python 测试框架
- FastAPI TestClient - API 测试客户端

### 测试架构
```
tests/
└── test_api.py     # 完整测试套件
    ├── TestContext     # 测试上下文（共享 token 和 ID）
```

### 运行测试
```bash
cd backend

# 运行所有测试
python -m pytest

# 运行特定测试类
python -m pytest tests/test_api.py::TestDataScope -v

# 运行单个测试
python -m pytest tests/test_api.py::TestAuth::test_login_superadmin -v

# 或使用批处理脚本
run_tests.bat
```

## 测试中发现的 Bug 及修复

### Bug 1: React Query 缓存未清除
**现象**: 登录不同用户后，仍然能看到上一个用户的数据
**原因**: 登录/登出时未清除 React Query 缓存
**修复**:
- `Login.tsx`: 登录前添加 `queryClient.clear()`
- `App.tsx`: 登出时添加 `queryClient.clear()`

### Bug 2: limit 参数超限导致 422 错误
**现象**: 客户列表页面无数据但控制台报 422 错误
**原因**: 前端使用 `limit=500` 但后端限制 `le=100`
**修复**:
- `CustomerList.tsx`: `limit: 500` → `limit: 100`
- `CustomerMap.tsx`: `limit: 500` → `limit: 100`

### Bug 3: 地图和列表数据不一致
**现象**: 张伟登录后，客户分布显示 8 个客户，但列表也是 8 个（应该是 6 个有坐标的）
**原因**:
1. 多个旧 uvicorn 进程运行在端口 8000，服务旧代码
2. Python `__pycache__` 缓存旧字节码
**修复**:
- 杀掉所有旧 Python 进程
- 清除 `__pycache__` 目录
- 重启 uvicorn 服务

### 测试经验总结
1. API 测试通过不代表前后端集成正常，需要人工验证
2. 多进程/缓存问题在本地开发时容易被忽视
3. React Query 缓存管理需要在用户切换时特别注意
4. 前端参数需要与后端 API 限制保持一致
