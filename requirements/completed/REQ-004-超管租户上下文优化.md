# REQ-004 超管租户上下文优化

## 需求概述
优化超级管理员的用户体验，增加租户上下文切换功能，解决超管操作租户级资源时归属不明确的问题。

## 问题分析

### 当前问题
1. **模板/字段创建问题**：超管创建模板时 `tenant_id=NULL`，资源无法被租户使用
2. **员工管理混乱**：超管看到所有租户员工，新建员工无法指定归属租户
3. **缺乏租户视角**：超管无法以某租户管理员身份查看和管理数据
4. **菜单结构不清**：平台级和租户级操作混在一起

### 目标
- 超管可以切换到任意租户的管理视角
- 切换后的操作都归属于选定的租户
- 清晰区分"平台管理"和"租户管理"两种模式

## 技术方案

### 1. 前端改动

#### 1.1 AuthContext 扩展
```typescript
interface AuthContextType {
  // ... 现有字段
  selectedTenantId: number | null;      // 当前选中的租户ID
  selectedTenant: Tenant | null;        // 当前选中的租户信息
  selectTenant: (tenant: Tenant) => void;  // 选择租户
  exitTenantMode: () => void;           // 退出租户模式
  isInTenantMode: boolean;              // 是否在租户管理模式
}
```

#### 1.2 Header 改动
- 超管登录后，显示"平台管理"标识
- 进入租户模式后，显示租户名 + "退出"按钮
- 使用不同背景色区分两种模式

#### 1.3 菜单改动
```
平台管理模式：
├── 租户管理

租户管理模式：
├── 员工管理
├── 客户管理
└── 系统配置
    ├── 模板管理
    └── 字段管理
```

#### 1.4 API 请求改动
- 超管在租户模式下，请求自动带上 `X-Tenant-Id` Header

### 2. 后端改动

#### 2.1 deps.py 修改
```python
def get_effective_tenant_id(request: Request, current_user: User) -> int | None:
    """获取有效的租户ID"""
    # 超管可以通过 Header 指定租户
    if current_user.is_super_admin:
        header_tenant = request.headers.get("X-Tenant-Id")
        if header_tenant:
            return int(header_tenant)
    return current_user.tenant_id
```

#### 2.2 各路由修改
- 模板、字段、用户、客户的创建/查询使用 `get_effective_tenant_id`

## 验收标准

1. 超管登录后默认只看到"租户管理"
2. 点击某租户"进入管理"后，切换到该租户视角
3. 在租户模式下创建的模板/字段/员工都归属该租户
4. 可以点击"返回平台"退出租户模式
5. 租户管理员和普通员工行为不受影响
