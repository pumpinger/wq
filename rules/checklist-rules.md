# 检查清单规则

> 各类操作的检查清单，确保不遗漏关键步骤。

## 需求开发检查清单

### 开始前
- [ ] 需求文档是否清晰？有疑问及时确认
- [ ] 是否已创建功能分支？(dev-xxx)
- [ ] 是否更新了 requirements/INDEX.md？
- [ ] 是否检索了 context/experience/ 相关经验？

### 开发中
- [ ] 命名是否符合项目规范？
- [ ] 组件位置是否合理？
- [ ] 是否遵循表单类型安全规范？
- [ ] API 定义是否符合规范？

### 提交前
- [ ] 代码是否有 lint 错误？
- [ ] TypeScript 类型是否完整？
- [ ] 是否有硬编码的值需要提取？
- [ ] commit message 是否清晰描述变更？

### 完成后
- [ ] 需求文档是否移到 completed/？
- [ ] 是否有值得沉淀的经验？
- [ ] requirements/INDEX.md 是否更新？

## Bug 修复检查清单

### 开始前
- [ ] 是否创建 bug-xxx 分支？
- [ ] 是否理解 bug 的根本原因？

### 修复后
- [ ] 是否验证了修复效果？
- [ ] 是否影响了其他功能？
- [ ] commit message 是否关联了 bug ID？
- [ ] 是否需要记录到 experience/？


## 代码 Review 检查清单

- [ ] 命名是否符合规范？
- [ ] 是否有安全隐患？
- [ ] 是否有性能问题？
- [ ] 是否有更好的实现方式？
- [ ] 是否有遗漏的边界情况？
